# Website review — 22 September 2026

Scope: PR [#114](https://github.com/bresca-ai/TrailReplay/pull/114), the current website checkout, and code outside the PR. GitHub reports the PR as merged. Its published base is `63348e3`, head `bc051df`; the local checkout also contains release-governance commit `2f525c4` and pre-existing uncommitted work. Those existing changes were preserved. Nothing was committed, pushed, or deployed by this review.

Review work was split across GPT-5.6 Sol for replay/export, Terra for frontend data/state/imports, and Luna for server endpoints. The coordinating review covered integration, build/release, SEO, dependencies, browser smoke checks, and review of the agents' patches.

The architecture has useful boundaries: store slices, pure route/recipe utilities, focused map hooks, and separate export helpers. The main remaining weaknesses are export lifecycle recovery, input resource limits, and duplicated preview/export presentation logic. Passing unit tests alone does not settle those issues.

## Remaining actionable findings

1. **P2 — interrupted email delivery still needs reconciliation.** `functions/api/exports/[jobId]/complete.js` deliberately blocks resending from `emailing` and `delivery_unknown`. This prevents duplicate sends but does not restore unattended delivery after process termination. Durable recovery needs a claim lease, persisted provider outcome/message ID, and immutable per-job payload/token state. Confirmation/unsubscribe hashes are currently stored once per lead and can be replaced by another export job, invalidating older links. The [Cloudflare Send API](https://developers.cloudflare.com/api/resources/email_sending/methods/send/) does not document an idempotency key or per-message reconciliation lookup; that conclusion is an inference from its published surface. [Cloudflare event logs](https://developers.cloudflare.com/email-service/observability/metrics-analytics/) can assist manual investigation. [Resend idempotency keys](https://resend.com/changelog/idempotency-keys) have a 24-hour window and require identical request parameters; adding a header alone would not make regenerated tokens safe. These lifecycle problems predate PR #114.

2. **P3 — annotation entrance differs between preview and video.** `index.css:371` animates opacity for 280 ms; `drawExportFrame.ts:138–223` paints text at full opacity. DOM bounding rectangles include the current transform, but the opacity and wall-clock animation are not tied to encoded time. Share deterministic presentation timing or explicitly align the two renderers. Verify actual encoded frames at 30 and 60 fps.

## Further improvements to plan

- **Derived route work:** `useComputedJourney` has eight consumers and computes both static geometry and per-frame values. Consumers that only need geometry still subscribe to all playback changes. Split stable geometry from live playback selectors, then profile long routes before claiming a frame-rate improvement. Media import geometry is now cached, but projection still scans route segments per file; evaluate a spatial index before increasing import concurrency.
- **Accessibility:** audit modal focus/keyboard behavior and remaining form associations. The targeted name/label fixes and viewport smoke check are not a screen-reader audit.
- **Server lifecycle:** the new tests cover upload races with mocked D1/R2; add deployed-runtime integration coverage. Plan retention for abandoned export rows and preserve fresh opt-in timestamps when users opt in again after unsubscribing. Ambiguous D1 upload commits deliberately retain their staged object to avoid deleting an accepted upload, so lifecycle cleanup remains necessary.
- **Provider transparency:** PR #114 adds `maps.mail.ru` as a final Overpass fallback. It receives route bounding boxes after earlier providers fail. Make the provider choice and the information sent visible in product/privacy documentation; this review did not change provider policy.
- **Dependency maintenance:** `npm audit` reported 9 affected dependency entries: 1 low, 4 moderate, 3 high, 1 critical. The [MapLibre advisory](https://github.com/advisories/GHSA-jrc7-96c5-q579) concerns untrusted attribution HTML and is patched in 6.4.1. This app disables the attribution control and uses static attribution strings, so the review did not demonstrate a reachable exploit. Plan a tested major-version upgrade rather than force-upgrading the map engine during this patch. Lockfiles were left unchanged.
